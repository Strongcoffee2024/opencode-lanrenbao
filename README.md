## 🎯 系统概述

基于 **Obsidian + OpenCode** 构建的个人知识管理系统，专注于 **自媒体内容创作** 和 **知识积累复用**。

**核心理念**:
- 📚 知识可积累、可复用
- 🔄 从原始素材 → 结构化知识 → 创作灵感
- 🎬 支持小说写作、AI 工具学习、创作者方法论等主题

## 📋 标准工作流（文档摄入）

### 完整流程

```
1️⃣ 扫描 raw/ → 发现新文件
    ↓
2️⃣ 判断文件大小
    ├─ 小文件 (<10KB) → 直接处理
    └─ 大文件 (≥10KB) → 分割为章节
        ↓
3️⃣ 单次处理一个小文件
    ├─ 读取内容
    ├─ 解析理解
    ├─ 提取核心概念
    ├─ 转换为 Wiki 格式
    └─ 写入 wiki/对应目录
    ↓
4️⃣ 更新索引和进度
    ├─ wiki/index.md
    └─ context/active.md
    ↓
5️⃣ ⚠️ 停止并询问
    └─ "是否继续处理下一个文件？"
```

## 📝 Wiki 文章格式规范

### 模板结构

```markdown
---
created: YYYY-MM-DD
source: raw/子目录/文件名
tags: [标签 1, 标签 2, #Anki]
---

# 文章标题

## 核心概念
> 一句话总结这个概念是什么

## 详细解析
- 关键点 1
- 关键点 2
- 关键点 3

## 相关概念
- [[相关概念 1]]
- [[相关概念 2]]

## 创作灵感小结
> 这个知识点可以如何变成自媒体内容？
> - 选题方向：xxx
> - 角度：xxx
> - 形式：图文/视频/短文

## 来源
- 原始文件：[[raw/子目录/文件名]]
```

### 硬性要求

- ✅ **语言**: 必须用中文（强制）
- ✅ **Frontmatter**: 必须有 `created`, `source`, `tags`
- ✅ **双向链接**: `[[wikilink]]` 格式
- ✅ **Callout**: `> [!info]` 等 Obsidian 语法
- ✅ **标签**: 至少包含分类标签，复习相关加 `#Anki`

## 🚦 故障排查

### 问题：任务中断后继续处理

**解决**: 直接发送「继续处理」指令，系统自动读取进度

### 问题：文件编码错误

**解决**: 使用 `workspace/split_cunmang.py` 按章节分割（支持 GBK 编码）

### 问题：去重判断

**机制**: 创建文件时自动比较，内容相同则跳过，内容不同则更新覆盖
